# 페이지: `/courses` — 강의 검색

> 페이지 설계 문서 — 한 페이지당 한 파일. 전체 목록·라우팅은 [`index.md`](./index.md).
> 공통 작성 항목은 `index.md` §8.

## 1. 목적

학기 강의 카탈로그(현재 고려대 세종캠 2026-1 `sample_data.csv` 파싱본)를 사용자가 **검색·필터·정렬**해서 보고, 마음에 드는 강의를 **"내 풀"** 에 담는다. 이 풀이 `/timetable` 페이지의 후보(`PreferenceVector.courses`)가 된다.

페이지의 단일 책임은 *카탈로그 탐색과 풀 편집*이다 — 시간표 추천을 여기서 직접 돌리지 않는다(분리).

## 2. 진입 경로

- URL: `/courses`
- 인증 필요: 예 (`<ProtectedRoute>`)
- 어디서 오는가: 메인 "강의 검색" 카드, `/timetable` 좌측 "내 풀 편집"

## 4. 상태(state)

페이지 로컬:
- `catalog: Course[]` — 서버에서 받은 카탈로그(메모 캐시 + sessionStorage 권장)
- `filters: { q, categories, requirements, creditMin, creditMax, days, buildings, professor, startMin, endMin }` — 모든 필터 한 객체
- `sort: "credit" | "name" | "id"`
- `selectedIds: Set<CourseId>` (= 풀)

전역(컨텍스트):
- `myPool: Course[]` 또는 `myPoolIds: Set<CourseId>` — 다른 페이지(`/timetable`, `/`)에서 공유

영속화:
- 데모 단계: `localStorage["my_pool_ids"]` JSON(String[]). 새로고침에 살아남음.
- 향후(DB Phase 2): `preference_courses` 테이블로 서버 저장(별도 라우트). 본 페이지 파일에서는 *프론트 책임*만 정의하고, 영속 정책은 서버 영역으로 위임.

## 5. 사용 API

| 메서드 | 경로 | 요청 | 응답 | 용도 |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/timetable/sample-courses` | — | `SampleCoursesResponse { courses: Course[], source }` | 카탈로그 로드(현재 유일한 카탈로그 소스) |

현재 서버에는 검색 전용 라우트가 없다 — **필터·정렬·검색은 전부 클라이언트**에서 한다(38행 규모에서 충분히 빠르다).

> 향후 (DB Phase 1 완료 후, 카탈로그가 수천 행 규모가 되면):
> `GET /api/v1/courses?q=...&category=...&credit_min=...` 같은 서버측 검색 라우트가 권장된다. 본 페이지 파일은 그 시점에 §5 표만 갱신하면 된다 — UI는 그대로.

에러 코드 매핑 (이 페이지에서 만날 만한 것):

| code | HTTP | 친화 메시지 |
| --- | --- | --- |
| 네트워크 실패 | — | "강의 카탈로그를 불러오지 못했어요. 잠시 후 다시 시도해 주세요." + 재시도 |
| `INTERNAL` | 500 | 동상 |

## 7. 인터랙션 (Happy Path)

1. 진입 → 카탈로그 로드(`fetchSampleCourses()`). 캐시가 있으면 즉시 표시, 백그라운드 갱신.
2. 사용자가 좌측 필터 조정 → `filters` 변경 → 결과 리스트가 즉시 재계산(클라이언트 메모이즈). URL 쿼리에는 *반영하지 않음*(데모; 차후 SEO·공유 필요 시 사용)
3. 사용자가 "+ 풀에 담기" → `selectedIds` 에 추가 → 풀 패널과 행의 체크 상태 동기 갱신. localStorage 즉시 저장.
4. 사용자가 "시간표 짜러 가기" → `/timetable` 로 이동. 시간표 페이지는 진입 시 myPool을 폼 초기로 채운다.
5. 풀에서 강의 제거는 두 곳 모두에서 가능(행의 토글, 풀 패널의 ×).

## 8. 상태 — 로딩 / 에러 / 빈

- **로딩**: 결과 리스트 자리에 스켈레톤 N행. 필터 패널은 비활성이 아니라 *조작 가능* 으로 둔다(로드가 길어도 사용자가 미리 조건을 설정).
- **에러(카탈로그 실패)**: 결과 영역 가운데 ErrorState + "다시 시도" 버튼. 풀 패널은 그대로 표시(이전 캐시).
- **빈(필터 결과 0)**: "조건에 맞는 강의가 없어요. 필터를 줄여 보세요." + "필터 초기화" 버튼.
- **빈(풀 0)**: 풀 패널에 "왼쪽에서 +로 담아 보세요." 안내. "시간표 짜러 가기" 버튼은 비활성(또는 안내 툴팁).

## 10. 열린 항목 / 향후

- **카탈로그 출처**: 현재 `/timetable/sample-courses`(고려대 세종캠 2026-1 sample_data.csv). DB Phase 1 적용 후 같은 라우트가 DB에서 읽어오게 *서버 내부에서* 교체 — 프론트 변화 없음. 진짜 검색 라우트로의 이동은 카탈로그 규모가 커진 뒤.
- **풀 영속화**: localStorage → 서버 `preference_courses`(DB Phase 2). 마이그레이션 시 페이지는 그대로 두고 `src/api/` 만 교체.
- **상세 정보 깊이**: 현재 `Course` 스키마(`app/schemas/common.py`)에 있는 필드만 보여준다. 강의 계획서(syllabus) 같은 외부 데이터는 비-목적(`base/product.md` §2.3 친구 매칭 등과 마찬가지로 범위 밖).
- **수강신청 안내**: 본 페이지는 "추천 풀을 만들기"가 목표지 수강신청 시스템 통합이 아님. 그건 별도 프로젝트.
