# 페이지: `/` — 메인 (허브)

> 페이지 설계 문서 — 한 페이지당 한 파일. 전체 목록·라우팅은 [`index.md`](./index.md).
> 공통 작성 항목은 `index.md` §8.

## 1. 목적

로그인 후 처음 도착하는 **결정 지연 페이지가 아니라 빠른 분기점**. 사용자는 여기서 두 가지 중 하나를 고른다: 강의를 모으러 갈지(`/courses`), 모은 풀로 시간표를 짤지(`/timetable`). 메인 페이지가 자체적으로 일을 시키지 않는 게 핵심이다 — *허브로서 가볍게* 유지(`base/product.md` §4 단순함 우선).

## 2. 진입 경로

- URL: `/`
- 인증 필요: 예 (`<ProtectedRoute>` 자식)
- 어디서 오는가: 로그인 직후, 로고 클릭(전역 헤더), `/timetable`/`/courses`에서 "메인으로" 액션

## 3. 레이아웃

공통 셸(헤더) 안에 본문 두 카드. 데스크톱 우선 — 카드 두 개를 가로로 나란히.

```
┌────────────────────────────────────────────────────────────┐
│ [로고/타이틀]                       사용자명  [로그아웃]      │ ← 공통 헤더
├────────────────────────────────────────────────────────────┤
│                                                            │
│   안녕하세요, {display_name 또는 email}님 👋               │  ← 인사 (옵셔널 1줄)
│   이번 학기 시간표를 어떻게 시작할까요?                       │
│                                                            │
│   ┌─────────────────────┐    ┌─────────────────────────┐   │
│   │  🔍                  │    │  📅                      │   │
│   │  강의 검색            │    │  시간표 짜기              │   │
│   │  카탈로그에서 강의을    │    │  모은 풀로 최적 시간표를    │   │
│   │  찾아 내 풀에 담기.    │    │  추천받기.                │   │
│   │                     │    │                          │   │
│   │  [ 강의 보러 가기 ▸ ]  │    │  [ 짜러 가기 ▸ ]          │   │
│   └─────────────────────┘    └─────────────────────────┘   │
│                                                            │
│   (작은) 내 풀: 12 강의 · 마지막 시간표: 어제                  │  ← 옵셔널 상태 줄
│                                                            │
└────────────────────────────────────────────────────────────┘
```

- 카드는 동일 크기·동일 무게. 한 쪽이 추천처럼 보이지 않게(허브 페이지의 중립성).
- 모바일 좁은 폭에서는 카드 세로로 쌓이지만, 현재 product.md §2.3 비-목적에 따라 데스크톱 보장 우선.
- 인사 한 줄은 환영 토스트(가입 직후)가 있으면 그 자리에 노출하고, 평소엔 사용자명만 가볍게.

## 4. 상태(state)

페이지 자체는 거의 상태가 없다(허브). 다만 옵셔널 "상태 줄"을 보여주려면 다음을 전역에서 읽는다:

- `currentUser: UserPublic` — 헤더·인사용
- `myPool: Course[]` — 강의 검색에서 모은 풀(전역 컨텍스트 또는 localStorage)
- `lastSolveAt?: string` — 최근 `/timetable/solve` 호출 시각(선택 — UX 보강용, 없어도 됨)

상태 줄은 데이터가 0/없음이면 자연스럽게 숨긴다(empty-by-omission).

## 5. 사용 API

본 페이지는 자체 호출이 거의 없다. 단:

- `<ProtectedRoute>` 가 마운트 시 1회 `GET /api/v1/auth/me` 를 호출해 토큰 검증(이미 캐시된 사용자가 있어도 만료 확인). 본 페이지는 그 결과를 props/Context로 받아 표시만.
- 상태 줄에 "내 풀 N개"를 보여주려면 강의 검색 페이지에서 가공한 풀(localStorage 또는 Context)을 읽기만. 별도 서버 호출 없음.

> 향후 DB Phase 2 (`claude/server/db/preference_sets.md`) 도입 시:
> `GET /api/v1/preference-sets/recent` 같은 라우트가 생기면 "최근 시도 1줄" 추가 가능.
> 이 의존은 서버 영역으로 위임 — 본 페이지는 라우트가 생기기 전까지 상태 줄을 표시하지 않는다.

## 6. 컴포넌트 분해

```
<MainPage>
├─ <Header />                    // 공통 셸이 제공 (사용자명·로그아웃)
└─ <HubBody>
   ├─ <Greeting />               // 1줄 인사 + 환영 토스트(있을 때)
   ├─ <HubCards>
   │   ├─ <HubCard to="/courses"   icon="search"   ... />
   │   └─ <HubCard to="/timetable" icon="calendar" ... />
   └─ <StatusLine />             // 옵셔널 — myPool/lastSolveAt 있을 때만
```

`<HubCard>` 는 라우터의 `<Link to>` 로 이동. tab/Enter 키 모두 활성화되도록 div 대신 anchor/button 사용.

## 7. 인터랙션 (Happy Path)

1. 로그인 직후 메인 진입. 환영 토스트 3초 노출 후 자동 dismiss.
2. 사용자가 두 카드 중 하나 클릭 → 해당 라우트로 push 이동(replace 아님 — 뒤로가기로 메인 복귀 가능).
3. (옵셔널) 상태 줄에 "내 풀 N개" 가 있으면 그 자체가 "이미 풀이 있다 → 시간표 짜기"의 시각적 힌트 역할.

## 8. 상태 — 로딩 / 에러 / 빈

- **로딩**: 본 페이지 자체에는 로딩이 거의 없다 — `<ProtectedRoute>` 의 세션 확인 동안 풀스크린 LoadingState가 잠깐 뜨고, 메인은 그 다음에 바로 그려진다.
- **에러**: `/me` 검증 실패는 `<ProtectedRoute>` 가 `/login` 으로 리다이렉트로 처리한다. 메인 안에서는 별도 에러 상태 거의 없음. (헤더의 로그아웃 실패 같은 부분은 헤더 컴포넌트가 자체 처리)
- **빈 상태**: 풀이 0이고 최근 시도가 없어도 본 페이지는 "허브"라 빈 상태가 따로 없다 — 두 카드 자체가 다음 행동을 안내한다. 다만 텍스트를 풀 유무에 따라 미세 조정 가능(예: 풀이 있으면 "이어서 시간표 짜기", 없으면 "강의 검색부터 시작해 보세요").

## 9. 나가는 길

| 액션 | 도착 |
| --- | --- |
| "강의 검색" 카드 | `/courses` |
| "시간표 짜기" 카드 | `/timetable` |
| 헤더의 로그아웃 | `/login` (토큰 제거 후 replace) |
| 헤더의 로고 | `/` (자기 자신 — 새로 그려짐, 토스트는 dismiss됨) |

## 10. 열린 항목 / 향후

- **추천 분기**: 두 카드를 동일 비중으로 두지만, 풀이 0이면 "강의 검색부터" 같은 약한 추천을 살짝 더하는 게 UX적으로 자연스럽다. user-experience.md 페르소나 확정 후 결정.
- **빠른 액션**: "최근 시도 다시 보기" 같은 1-탭 진입 버튼은 DB Phase 3(`scheduled_results`) 가 도입돼야 의미가 생긴다. 그 전에는 안 둔다.
- **온보딩 1회**: 가입 직후 첫 방문 시 카드 위에 1줄 가이드(예: "먼저 강의를 골라 풀을 만들고, 시간표를 추천받아요.")를 띄울지. 환영 토스트와 중복되지 않게 조율.
