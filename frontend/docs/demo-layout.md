## 0. 데모가 보여주는 것 / 생략하는 것

**보여준다**

- 클로드형 3분할 한 페이지에서 "입력 → 후보 시간표 → 선택"의 전체 흐름.
- 추천 후보 N개를 한눈에 비교(우측 리스트)하고, 고른 하나를 크게 확인(중앙 격자).
- 결과 근거(포함/제외 사유·점수 분해)를 채팅 형태로 읽는 경험.

**생략한다 (데모 한정)**

- 실제 알고리즘 호출. 시간표 생성 엔드포인트는 서버에 아직 없으므로 **샘플 데이터**
  (`src/lib/sampleData.ts`)로 채운다. 화면에는 항상 "샘플" 배지를 표시한다
  (가짜 응답을 실제처럼 위조하지 않기 위함 — `base/CLAUDE.md` §3.5).
- 실제 로그인/계정 시스템. 좌측 계정 영역은 **플레이스홀더**.
- 영속 저장(DB). "저장한 과목"은 데모에서는 메모리/로컬 상태로만.

## 1. 전체 레이아웃 (PC 우선)

`product.md` §2.3이 모바일 우선을 비-목적으로 두므로 **데스크톱 우선** 3-column.

```
┌────────────────┬─────────────────────────────────┬─────────────────────┐
│  좌 사이드바     │            중앙 (메인)           │   우 후보 리스트      │
│  240–280px      │        가변 (최소 ~480px)        │   320–360px         │
│  고정           │                                 │   스크롤             │
│                │  ┌── 선택된 시간표 ───────────┐  │  추천 후보 (N개)      │
│ ▸ 계정 상태      │  │  요일 × 시간 주간 격자      │  │  ┌───────────────┐  │
│ ▸ 저장한 과목    │  │  + 점수/학점 요약          │  │  │ 추천 1   92점   │  │
│ ▸ 새 대화        │  └───────────────────────────┘  │  │ 미니 격자 미리보기│  │
│ ▸ 지난 대화      │                                 │  └───────────────┘  │
│ ▸ 설정          │  ┌── 채팅 ───────────────────┐  │  ┌───────────────┐  │
│                │  │  메시지 스트림 (사용자/AI)  │  │  │ 추천 2   88점   │  │
│                │  │   …                        │  │  └───────────────┘  │
│                │  │  [ 입력창 ____________  ↵ ] │  │   …                 │
│                │  └───────────────────────────┘  │                     │
└────────────────┴─────────────────────────────────┴─────────────────────┘
```

- 최소 권장 폭 ~1100px. 그 이하에서는 우측 리스트를 접고(토글) 중앙만,
  더 좁으면 좌측 사이드바를 오버레이 토글로. (데모에서는 데스크톱만 보장)
- 세 영역은 각자 독립 스크롤. 헤더는 생략하거나 좌측 상단에 로고/타이틀만.

### 1.1 색상 토큰 (기본 팔레트)

마룬 `#7C001A` + 크림 `#F6F3EE`를 **위주로** 사용한다. 정돈되고 신뢰감 있는 톤
(`product.md` §3.1)에 부합하는 따뜻한 조합.

| 역할 | 색 | Tailwind 토큰 | 쓰임 |
| ---- | --- | ------------- | ---- |
| 배경(표면) | `#F6F3EE` | `cream` / `cream-100` | 페이지 바탕, 헤더 |
| 강조/액션 | `#7C001A` | `brand-600` | 기본 버튼, 활성 탭/카드, 링크, 포커스 링, 제목 |
| 강조 hover | `#660016` | `brand-700` | 버튼 hover |
| 강조 연한 톤 | `#FBEDEF`·`#F6D9DD` | `brand-50`·`brand-100` | 보조 버튼 배경, 강조 영역 |
| 본문 텍스트 | `#292524` | `ink` | 제목 외 본문 |
| 보조 텍스트 | `#57534E`·`#A8A29E` | `ink-soft`·`ink-faint` | 설명·라벨 |

- 카드 표면은 흰색을 유지해 크림 배경과 대비를 준다(가독성).
- 시간표 격자의 **주 카테고리(전공)는 마룬**으로 통일하고, 나머지 카테고리는
  구분을 위해 따뜻한 계열(복수전공 rose · 교양 amber · 일선 stone)로 둔다.
- 상태 색(제외=rose, 포함=emerald)은 의미 전달용 기능 색으로 소량만 사용.
- 색상은 스타일 결정이라 `frontend/progress.md`에는 기록하지 않는다
  (`base/CLAUDE.md` §5.2 — 스타일 손질은 git 커밋으로 충분).

## 2. 영역별 상세

### 2.1 좌측 사이드바 — 계정 · 저장한 과목

| 블록 | 내용 | 데모 처리 |
| ---- | ---- | --------- |
| 계정 상태 | 아바타 + 닉네임 + (예: "국민대 / 2026-1학기") | 플레이스홀더 더미 |
| 저장한 과목 | 사용자가 모아둔 강의 풀(후보) 목록. 칩/리스트로 표시, 추가·제거 | 메모리 상태(`Course[]`). 추가 시 후보 재생성(샘플) |
| 새 대화 | 새 시간표 세션 시작 버튼 | 상태 초기화 |
| 지난 대화 | 과거 세션 목록 (클로드 사이드바의 대화 히스토리 느낌) | 더미 1~2개 |
| 설정 | 학점 범위·가중치 등 기본 조정 진입점 | 모달/패널(후속) |

"저장한 과목"이 곧 `PreferenceVector.courses`(후보 풀)의 원천이다. 좌측에서 과목을
넣고 빼면 중앙·우측 결과가 다시 계산된다(데모는 샘플로 갱신).

### 2.2 중앙 — 채팅 + 선택된 시간표

두 블록을 세로로 쌓는다. **위: 선택된 시간표 / 아래: 채팅.**

- **선택된 시간표**: 우측 리스트에서 고른 후보 하나를 주간 격자(요일 × 시간)로 크게
  렌더링. 기존 `src/components/TimetableGrid.tsx`를 그대로 재사용. 위에 점수·학점·강의
  수 요약. (격자 디자인·색상 범례는 이미 구현됨)
- **채팅**: 사용자가 자연어로 요청("월 공강, 전공 위주 15학점")하고, 시스템이 후보를
  만들어 우측에 채우면서 채팅에는 요약·근거(포함/제외 사유·점수 분해 핵심)를
  답한다. 입력창은 하단 고정, 메시지 스트림은 그 위에서 스크롤.

> ⚠️ **채팅 입력은 `product.md` §5.2의 "자유 텍스트 → LLM 수치화"(현재 보류)
> 기능을 데모에서 미리 시연하는 자리다.** §4.4 불변항은 유지된다: **시간표 결정은
> 항상 알고리즘**이 하고, LLM은 (a) 자유 텍스트의 수치화 (b) 결과의 자연어 설명에만
> 관여한다. 데모에서 채팅 응답은 스크립트/샘플이며, 실제 도입 시에는 LLM이 만든
> 수치화 결과(PreferenceVector로의 변환)를 **사용자가 확인하는 단계**가 필수다.
> 프론트는 LLM을 직접 호출하지 않는다 — 서버 경유(`architecture.md` §3.1).

### 2.3 우측 — 시간표 후보 리스트

- `SelectionResult.ranked_schedules`(상위 N개, N=3~5)를 점수 내림차순 카드로 나열.
- 각 카드: 순위 배지("추천 1") + 총점 + 학점 + **미니 주간 격자 미리보기**(축소판)
  + 핵심 한 줄(예: "CS101 01분반 · 전공 위주").
- 카드 클릭 → 중앙 "선택된 시간표"가 그 후보로 갱신(현재 선택 카드 하이라이트).
- 상단에 정렬/필터(점수순·이동시간순 등)는 후속.

## 3. 데이터 매핑

| 화면 영역 | 연결되는 타입/상태 (`src/types/timetable.ts`) |
| --------- | --------------------------------------------- |
| 좌·저장한 과목 | `Course[]` (= `PreferenceVector.courses` 원천) |
| 좌·계정 | (데모) 더미 객체 |
| 중앙·선택된 시간표 | `ScoredSchedule`(선택된 후보) + 풀과 조인해 `Course.times` 배치 |
| 중앙·채팅 | 메시지 배열 `{ role: "user" | "assistant", text }[]` (데모 로컬) |
| 우·후보 리스트 | `SelectionResult.ranked_schedules: ScoredSchedule[]` |
| 후보 카드의 사유/설명 | `SelectionResult.course_rationale`, `notes` |

> 핵심 조인 규칙: 응답의 `ranked_schedules[i].courses`는 **강의 ID 목록만** 담는다.
> 화면은 좌측 "저장한 과목"(= 보낸 풀)과 ID로 조인해 시간/건물/교수 메타를 얻어
> 격자를 그린다. (서버는 Course 메타를 응답에 중복 포함하지 않는다는 잠정 가정 —
> 서버 계약 확정 시 재확인)

## 4. 인터랙션 흐름 (Happy Path)

1. **요청** — 사용자가 채팅에 자연어로 조건 입력 (또는 좌측에서 과목 추가).
   - 시스템: 입력 접수 표시(로딩), 우측 리스트 자리에 스켈레톤.
2. **후보 생성** — (데모) 샘플 `SelectionResult`를 우측 카드로 채우고, 채팅에
   "N개 후보를 찾았어요" + 핵심 비교 한두 줄.
3. **선택** — 사용자가 우측 카드 클릭 → 중앙 격자가 해당 시간표로 전환.
4. **근거 확인** — 채팅에서 "왜 PHIL100이 빠졌나요?" 류 질문 → 해당 강의의
   `course_rationale.detail`을 답으로 표시(데모는 사유 데이터에서 직접 매핑).
5. **조정** — 좌측에서 과목 추가/제거 또는 채팅으로 재요청 → 2번으로 루프.

## 5. 상태 (로딩 / 에러 / 빈)

기존 `src/components/States.tsx`를 재사용·확장.

- **빈 (초기)**: 우측·중앙 결과 영역에 "왼쪽에서 과목을 모으거나 아래 채팅으로
  시작하세요" 안내.
- **로딩**: 우측 카드 스켈레톤 + 채팅에 작성 중 인디케이터.
- **빈 (결과 없음/불가능)**: `infeasibility`가 있으면 "어느 제약을 풀면 되는지"
  안내(`resolution_hint`). `product.md` §4 우선순위 4번(불가능 입력 안내).
- **에러**: 서버 `{detail, code}`의 detail 원문 노출 금지 — 친화 메시지로 변환
  (`src/api/client.ts`의 코드 맵 재사용).

## 7. 접근성 · 반응성 메모

- PC 우선(≥1100px 보장). 좁아질 때 우측 접기 → 중앙 단일.
- 키보드: 우측 카드 목록 ↑/↓ 이동·Enter 선택, 채팅 입력 자동 포커스,
  좌측 과목 추가/제거 버튼 포커스 가시성.
- 색만으로 카테고리를 구분하지 않도록 카드에 텍스트 라벨 병기.
- 톤·문구 세부는 `user-experience.md`가 채워지면 거기에 맞춰 다듬는다(현재 잠정).

## 8. 협의·확정 필요 (열린 항목)

1. **채팅 = LLM 수치화 시연** — `product.md` §5.2 보류 기능. 데모 시연 범위와
   "사용자 확인 단계" 설계를 product/UX 차원에서 확정 필요(§4.4 불변항 유지).
2. **서버 계약 미확정** — 시간표 생성 라우트 경로와 요청/응답 envelope
   (`TimetableRequest`/`TimetableResponse`)는 잠정. 서버 팀과 `base/CLAUDE.md`
   §3.2 안전 순서로 확정.
3. **"저장한 과목" 영속성** — 데모는 메모리. 실제는 DB(서버 경유) 필요 여부.
4. **`user-experience.md` 비어 있음** — 페르소나·여정·인터랙션 톤 채워지면
   본 문서의 잠정 결정(문구·상태 처리)을 재정렬.
